# 002. 자체 PG 구현 전 선택 설정의 동작

- 상태: 대체됨 (003으로)
- 기록일: 2026-10-26
- 관련 이슈·PR: #3

## 해결하려던 문제

#3의 첫 작업은 PG 선택 설정이며 자체 PG 구현체는 후속 #4 범위다.
따라서 설정만 먼저 추가하는 시점에 `own`을 지정했을 때의 동작을 정해야 한다.
자체 PG 인증 계약과 기존 결제의 PG 식별·라우팅 정책도 아직 확정되지 않았다.

## 결정

2026-10-26 작업 담당자의 확인을 받아 다음과 같이 결정했다.

- `app.payment.gateway`가 없거나 `toss`이면 기존 Toss 구성을 사용한다.
- `own`을 지정하면 Toss 구성을 생성하지 않고, 자체 PG 구현체가 없으므로 필수 Gateway
  의존성을 만족시키지 못해 앱 시작을 중단한다. 자체 PG 대역 구현체는 추가하지 않는다.
- 자체 PG 설정은 `app.payment.own` 아래 주소·API 키·연결/응답 타임아웃을 예비 항목으로만 둔다.
  예비 키는 `base-url`, `api-key`, `connect-timeout`, `read-timeout`이며,
  환경변수는 각각 `OWN_PG_BASE_URL`, `OWN_PG_API_KEY`, `OWN_PG_CONNECT_TIMEOUT`,
  `OWN_PG_READ_TIMEOUT`이다. 연결/응답 타임아웃 기본값은 기존 Toss와 같은 3초/5초다.
  실제 인증 헤더·요청 필드·가맹점 식별 계약은 정하지 않는다.
- 테스트 프로필은 Toss를 명시해 로컬 `.env`의 선택값에 의존하지 않게 한다.

## 선택 이유

PG 선택값과 실제로 호출되는 제공자가 일치하도록 유지한다.
후속 구현 전에는 자체 PG가 활성화된 것으로 오인할 수 있는 상태를 만들지 않는다.

## 검토한 대안

- 자체 PG가 준비될 때까지 Toss 선택 설정만 추가하고 자체 PG 예비 설정은 보류한다.
- `own` 선택 시 기능을 비활성화하는 자체 PG 대역을 두는 방법은 구현체를 #4에서 추가하는
  작업 경계와 중복되며, 현재 승인·취소·조회 실패 계약도 필요해진다.

## 감수한 비용과 한계

자체 PG 구현 전 `own`을 지정한 앱이 시작되지 않는다.
미지정/Toss 동작은 유지한다. 자체 PG 예비 설정은 외부 API 인증 계약이 아니며,
기존 결제의 PG 식별·조회·환불·미완료 보상·롤백 정책을 해결하지 않는다.
자체 PG 실제 활성화 전 이 정책과 상태 매핑·조회 없음·멱등성 계약을 별도로 확정해야 한다.

## 다시 검토할 조건

자체 PG 구현체를 추가하거나 PG 팀의 인증·설정 계약이 확정될 때 검토한다.
