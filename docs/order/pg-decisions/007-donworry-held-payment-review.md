# 007. 돈워리 보류(HELD) 결제를 가맹점에서 "결제 확인 중"으로 다룬다

- 상태: 채택
- 기록일: 2026-11-04
- 관련 이슈·PR: DonWorry #492 · ADR-0064 4절·4-1 개정(DonWorry PR #510), 이 저장소 #26(웹훅) 위 PR
- 바꾸는 결정: [DonWorry 결제 연동](../donworry-payment-client.md) 2절의 "보류(HELD)도 결제 완료로 본다"를
  구매자 기준으로만 남기고, 가맹점·주문 처리 기준은 이 문서로 바꾼다.

## 해결하려던 문제

돈워리는 중위험 결제를 카드 승인 뒤 매입만 보류(`HELD`)하고 보안 직원 판정을 기다린다.
지금 CakeShop은 `HELD`를 결제 완료로 보고 일반 주문을 바로 픽업 준비로 넘겨서, 판정 전에 상품이 나갈 수 있다.
직원이 거절(`VOIDED`)하면 카드 청구가 풀리므로 이미 나간 상품은 손실이 된다.
돈워리 팀은 2026-11-03 회의에서 판정에 픽업 정보를 쓰지 않기로 했고, 2026-11-04 #492에서 손실을 가맹점 부담으로 바꿨다.
그래서 판정 전에 상품이 나가지 않게 하는 일은 가맹점(CakeShop) 몫이다.

## 결정

- 결제 완료는 지금처럼 한다(구매자는 기다리지 않는다). 돈워리 조회 결과가 승인된 `HELD`면 결제에
  `payments.gateway_held_at`을 기록한다.
- 일반 주문은 픽업 준비 대신 주문 확인 중(`UNDER_REVIEW`)으로 둔다. 수제 주문은 원래 주문 확인 중으로 가므로 표시만 남긴다.
- 돈워리가 `CAPTURED`(직원 승인)를 알리면 `payments.gateway_captured_at`을 기록하고, 아직 주문 확인 중인 일반 주문을 픽업 준비로 넘긴다.
  수제 주문은 관리자 제작 승인을 그대로 기다린다.
- `VOIDED`(직원 거절)는 기존 처리(이행 전 취소, 이행 뒤 유지)를 그대로 쓰고, 유지한 주문의 손실은 가맹점 부담으로 적는다.
- 구매자에게는 결제 검토 사실을 보이지 않는다. `UNDER_REVIEW` 이름을 "주문 확인 중"으로 바꿔 수제·일반이 함께 쓴다.
- 주문 확인 중인 일반 주문도 픽업 전이면 고객·가맹점이 취소할 수 있다(픽업 준비와 같은 규칙).
- 가맹점 화면의 "결제 확인 중" 표시·알림과 "고객 확인 후 진행"(확인 창·진행 기록)은 후속 PR에서 한다.
  진행 기록 컬럼도 그 PR에서 추가한다(쓰지 않는 컬럼을 미리 만들지 않는다).

## 선택 이유

- 새 주문 상태를 만들지 않고 `UNDER_REVIEW`를 다시 쓰면 DB CHECK·화면·알림·취소 규칙을 대부분 그대로 쓸 수 있다.
  구매자에게는 수제 주문과 같은 "주문 확인 중"으로 보여 결제 검토를 드러내지 않는다.
- 보류 여부를 주문이 아니라 결제(`payments`)에 둔다. 보류는 PG 결제의 상태이고, 판정 결과도 결제 단위(웹훅·조회)로 온다.
  주문 상태는 결제 상태를 보고 바꾼다.
- 판정 대기를 "보류 시각은 있고 매입 시각은 없음"으로 표현하면 웹훅·조회 배치가 같은 판정을 여러 번 보내도 한 번만 반영된다.

## 검토한 대안

- 새 주문 상태(예: `PAYMENT_REVIEW`)를 만든다. CHECK 제약, 전이 규칙, 모든 목록·집계·알림·취소 쿼리를 함께 바꿔야 하고
  구매자 화면에 결제 검토가 드러나기 쉽다.
- 결제 상태(`PaymentStatus`)에 보류를 넣는다. `DONE`을 전제로 한 환불·복구·정산 쿼리가 많아 영향이 크다.
- `HELD`면 결제 완료를 미룬다(구매자가 판정까지 대기). 판정이 몇 분에서 1시간까지 걸려 구매자가 기다릴 수 없다(DonWorry ADR-0064 버린 대안).
- 표시만 하고 주문은 픽업 준비로 넘긴다. 픽업 완료 버튼이 바로 열려 판정 전 출고를 막지 못한다.

## 감수한 비용과 한계

- 일반 주문에도 `UNDER_REVIEW`가 생기므로, `UNDER_REVIEW`를 수제 전용으로 가정한 화면(관리자 "검토 대기" 탭·대시보드 수제 집계 등)은
  후속 PR에서 일반 주문을 구분해 보여야 한다. 대시보드 수제 집계는 `custom_order` 조건이 있어 섞이지 않는다.
- 이 PR만 병합되면 가맹점이 판정 전에 일반 주문을 진행할 버튼이 없다(판정·취소만 가능). 후속 PR에서 확인 창과 기록을 붙여 연다.
- 판정 전에 결제가 이미 매입(`CAPTURED`)됐다면 보류 표시 없이 바로 픽업 준비로 간다. 보류를 놓친 것이 아니라 판정이 먼저 끝난 경우다.

## 다시 검토할 조건

돈워리가 보류 결제의 손실 부담이나 판정 목표 시간을 바꾸거나, 가맹점이 즉시 출고 업종이라 추가 본인 인증(DonWorry 2차 인증)을 붙일 때.
