# 자체 PG 연동 결정 기록

- **범위**: 자체 PG 연동 작업(GitHub 로드맵 이슈 #1과 하위 이슈)에서 내린 설계 결정
- **관련 문서**: [자체 PG 기능 명세](../pg-integration-spec.md), [프로젝트 공통 결정 기록](../../decisions/)

이 폴더는 자체 PG 연동 작업 전용 ADR(Architecture Decision Record)을 둔다. 프로젝트 전체에 걸친 결정은
`docs/decisions/`에 두고 이 폴더에 섞지 않는다. 업무 규칙과 기능 동작은 기능 명세가 정본이며, 이 폴더는
**왜 그렇게 정했는지**만 기록한다.

## 1. 작성 기준

다음 중 하나라도 해당하면 ADR을 작성한다.

1. 나중에 되돌리기 어렵다. 예: DB 구조, PG와의 외부 계약, 공개 Service 시그니처
2. 다른 도메인이나 팀원에게 영향이 간다.
3. 여러 방법 중 하나를 골랐고, 왜 골랐는지 나중에 다시 물을 만하다.

기준에 해당하지 않는 구현 선택은 PR 본문에만 남긴다.

## 2. 작성 절차

1. 작업 중 기준에 해당하는 선택을 만나면 혼자 정하지 않는다. 선택지와 추천안을 작업 담당자에게 먼저 묻는다.
2. 결정이 나면 결정을 반영한 PR에 ADR을 함께 넣는다. 결정만 있고 구현이 없으면 `docs` PR로 따로 올린다.
3. 결정을 아직 내릴 수 없으면 상태를 `제안`으로 두고, 관련 이슈의 `미결정`에 ADR 경로를 적는다.
4. 결정을 바꿀 때는 기존 ADR을 고치지 않는다. 새 ADR을 만들고, 기존 ADR의 상태를
   `대체됨 (NNN으로)`으로만 바꾼다.

## 3. 파일 이름

`NNN-주제.md` 형식으로 쓴다. 번호는 001부터 순서대로 붙이고, 주제는 영어 소문자와 `-`로 쓴다.

```text
001-payment-gateway-abstraction.md
002-payment-provider-column.md
```

## 4. 양식

```markdown
# NNN. 결정 제목

- 상태: 제안 | 채택 | 대체됨 (NNN으로)
- 기록일: YYYY-MM-DD
- 관련 이슈·PR: #N

## 해결하려던 문제

## 결정

## 선택 이유

## 검토한 대안

## 감수한 비용과 한계

## 다시 검토할 조건
```
