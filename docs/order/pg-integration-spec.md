# 자체 PG 연동 기능 명세

## 1. 결제 승인

- 결제 생성 시 `payments.provider`에 PG를 저장한다. `app.payment.gateway`의 기본값과 `toss`는
  `TOSS`, `own`은 `OWN`을 선택하며, 요청의 PG 값은 받지 않는다.
- 기존 결제는 결제 대기 상태를 포함해 모두 `TOSS`로 보존한다. 설정을 바꿔도 결제의 PG는 바꾸지 않는다.
- 결제창 설정·주문명 규칙·실패 코드 해석·승인·승인 상태 조회는 저장된 PG로 처리한다.
- 새 PG를 선택하려면 그 구현체가 있어야 한다. 자체 PG API·인증·상태 매핑·멱등성·결제창 계약은
  아직 미확정이며, 실제 구현 없이 `own`을 선택하면 앱 시작을 중단한다.
- 0원 결제도 생성 당시 선택값을 기록하지만 외부 승인·취소 API는 호출하지 않는다.

## 2. 결제 취소·환불

- 환불 요청과 재시도는 원 결제에 저장한 PG를 사용한다. 고객 취소·관리자 취소·수제 반려에 모두 적용한다.
- 환불 오류 뒤 상태 조회도 같은 PG를 사용한다. 다른 PG로 재시도하지 않는다.
- 기존 Toss 결제가 남아 있는 동안 Toss 구현체와 필요한 설정·인증 정보를 유지한다.

## 3. 결제 장애 복구

- 미완료 승인 보상·환불 재처리 요청에는 원 결제의 PG를 전달하며, 재기동 후에도 DB 기록에서 복원한다.
- PG 식별자가 누락되거나 해당 구현체가 없으면 실패로 남겨 복구 대상으로 유지하고 임의 PG로 보내지 않는다.
- 자체 PG 장애로 신규 결제를 Toss로 되돌리면 이후 생성한 결제만 `TOSS`로 저장한다. 기존 `OWN`
  결제의 조회·환불·미완료 복구는 자체 PG에서 계속 처리한다.
- 설정 복귀 시에도 자체 PG 구현체·설정·인증 정보를 제거하지 않는다. 자체 PG 결제가 생긴 뒤에는
  결제별 PG를 모르는 이전 바이너리로 되돌리지 않는다.
- 기존 식별자 UNIQUE 제약은 유지한다. 자체 PG 구현 전에 결제 키·멱등 키·환불 거래 키의 충돌 가능성을
  외부 계약과 함께 확인한다.
결정 근거와 제약은 [ADR 003](pg-decisions/003-payment-provider-routing.md)에 기록한다.
