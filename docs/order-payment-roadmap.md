# 주문·결제 기능 로드맵

> 주문·결제 기능의 **전체 위치, 선후관계, 작업 경계**를 Codex가 이해하기 위한 지도다.
> `기능_구현_현황_영역포함.xlsx`의 `F-xx` 한 행이 작업 단위와 기능 범위의 기준이다.
> 사용자가 특정 `F-xx`의 Issue 작성을 요청하면 이 로드맵과 해당 행으로 Issue 초안을 만들고, 사용자가 검토·등록한 GitHub Issue로 그 한 행의 인수 조건과 구현 상세를 확정한다.
> GitHub Issue·PR·브랜치는 구현 추적과 현재 작업 상세의 근거이며, 다른 `F-xx`의 범위를 현재 작업에 추가하는 근거가 되지 않는다.
> 이 문서의 상태값은 기능 목록 스냅샷이며 실제 코드 상태를 자동 판정하지 않는다.
> 현재 Issue·PR·브랜치·커밋 상태를 답하거나 문서 상태를 갱신할 때는 이 문서만 믿지 않고 GitHub와 로컬 브랜치를 먼저 다시 확인한다.

자체 PG 추가 작업은 [로드맵 이슈 #1](https://github.com/team-sweethan/cakeshop_refactoring/issues/1)에서
추적한다. 결제 서비스는 `PaymentGateway` 경계를 사용하고 기본 구현은 Toss다.
코드의 PG 주문 식별자는 `gatewayOrderId`이며 기존 DB 컬럼 `toss_order_id`는 유지한다.
아래 완료 이력의 Toss 표기는 당시 구현을 가리킨다.

## 1. 작업 경계

- 기능 목록의 **`F-xx` 한 행을 기본적으로 하나의 독립 Issue 후보**로 취급한다.
- 구현 직전 검토에서 독립 PR 하나로 종료할 수 없다고 확인되면, 사용자의 명시적 승인 후에만 하위 Issue로 나눈다.
- 현재 사용자가 지정한 `F-xx` 또는 그 행을 바탕으로 사용자가 검토·등록한 GitHub Issue만 현재 작업 범위다.
- 다른 `F-xx`는 선행·후속·관련 맥락이며 현재 Issue에 합치지 않는다.
- 다음 기능에 필요하다는 이유로 상태, API, DB 구조, Service, 화면, 스케줄러, 환불 흐름 등을 미리 구현하지 않는다.
- 선행 기능이 아직 준비되지 않았다면 현재 Issue에 흡수하지 않고 **의존성으로 식별**한다.
- `팀 결정 필요` 항목은 정책 확정 전 임의로 결정하거나 구현하지 않는다.
- `범위 제외`와 `후순위` 항목은 다른 기능 구현 중 필요해 보여도 선행 구현하지 않는다.
- 완료된 기능은 재사용할 기존 기반이며 현재 Issue에서 다시 설계하거나 확장하는 범위가 아니다.
- 현재 Issue를 끝내기 위해 다른 F-ID가 반드시 필요하다고 판단되면 범위를 확장하지 말고 필요한 F-ID 또는 정책을 먼저 명시한다.
- 로드맵에는 변하는 커밋 수나 작업 트리 상태를 기록하지 않는다. 현재 구현 상태는 해당 Issue·PR 링크와 로컬 브랜치 조회 결과로 확인한다.

### 관계의 의미

- **선행**: 현재 기능 전에 준비되어 있어야 하는 별도 기능 또는 정책
- **후속/관련**: 현재 기능과 이어지지만 별도 Issue로 유지할 기능
- **종료 경계**: 현재 기능이 책임지는 마지막 업무 지점

### 2차 범위 규칙

- F-06에서 F-07 결제를 미리 구현하지 않는다.
- F-07에서 F-10~F-14의 검토·제작 업무를 미리 구현하지 않는다.
- F-10에서 F-11/F-12/F-13의 행동 endpoint를 미리 구현하지 않는다.
- F-11에서 F-14 제작 완료·픽업 완료를 미리 구현하지 않는다.
- F-13에서 F-09 고객 응답을 미리 구현하지 않는다.
- F-08/F-11/F-12는 각자의 상태 전이에서 조건부 갱신 또는 행 잠금 등 **최소 원자성**을 보장한다. 세 업무의 전체 경쟁 조합 테스트와 공통 정리는 F-33에서 다룬다.
- 공통 환불이 필요하면 F-36을 사용하거나 선행 의존성으로 식별하고, 각 업무 Issue에서 새로운 범용 환불 체계를 따로 만들지 않는다.

## 10. 현재 F-ID 해석 예시

현재 작업이 `F-11 수제 주문 승인·제작 시작`이라면:

```text
선행
F-10 검토 목록
F-31 상태 계약
F-32 상태 이력
        │
        ▼
현재
F-11 승인·제작 시작
        │
        ├─ 별도 횡단 작업: F-33 경쟁 상태 검증·정리
        └─ 후속 업무: F-14 제작 완료·픽업 완료
```

F-11의 종료점은 **승인과 제작 시작**이다. F-14, F-12, F-08, F-33 전체를 현재 Issue에 포함하지 않는다. 단, F-11 자신의 상태 갱신은 동시 요청에도 한 번만 적용되도록 원자성을 보장한다.

다른 모든 `F-xx`도 같은 방식으로 `선행 → 현재 종료 경계 → 별도 후속`을 기준으로 해석한다.
